## Findings

### AG-01-未修复-高-branch scope 在脏工作区中静默宣称不完整结果
- **入口/函数**: `$model-review-skill` workflow → `review.mjs main()` → `collectContext(scope="branch")`
- **文件(行号)**: `skills/model-review-skill/SKILL.md:20-22`; `skills/model-review-skill/scripts/lib/context.mjs:45-48`
- **输入场景**: 当前功能分支既有相对 main 的 commits，又有尚未提交的 staged、unstaged 或 untracked 新改动；Skill 按指令“base 已知时优先 branch”运行。
- **实际分支**: `branch` 只执行 `git diff <base>...HEAD`，既不收集也不报告 working tree 状态；结果 coverage 只列出已提交文件。
- **预期行为**: 只读评审不能让用户误以为当前分支全部改动已覆盖。应明确拒绝脏工作区，或把未覆盖状态写入结果。
- **实际行为**: 命令成功并生成看似完整的 review，刚写完但未提交的代码完全遗漏。
- **直接证据**: branch path 没有 `git status` / cached / unstaged / untracked 检查；Skill 又推荐在 base 已知时优先该 scope。
- **影响**: 关键新代码漏审，用户基于虚假覆盖面合并或提交。
- **建议改法和验证点**: branch scope 运行前检查 `git status --porcelain --untracked-files=normal`，非空时以 `UNCOVERED_WORKTREE` 失败并提示选择 working-tree 或先提交/清理；同时把 Skill 指令改成仅对 clean、已提交分支使用 branch。增加 staged、unstaged、untracked 三种脏状态回归测试。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 高

- **输入场景**: 执行计划声明的 `git diff --check main...HEAD`。
- **实际分支**: Git 报告五处 `new blank line at EOF`。
- **预期行为**: 已声明 validation 应通过。
- **实际行为**: 分支未满足自身验收命令。

- **影响**: 最终质量 gate 失败。
- **建议改法和验证点**: 删除多余 EOF 空行并重跑 `git diff --check main...HEAD`。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 低
