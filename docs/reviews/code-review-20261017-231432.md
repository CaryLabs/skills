## Findings

### CR-01-未修复-高-敏感路径规则会漏掉常见 secrets 目录
- **入口/函数**: `collectContext()` → `isSensitivePath()`
- **文件(行号)**: `skills/model-review-skill/scripts/lib/context.mjs:5-10`
- **输入场景**: 工作区包含 `secrets/provider.json`、`.secrets/token.txt` 等未跟踪文件，且调用者启用 `includeUntracked`。
- **实际分支**: 路径片段只在等于 `secret` 或以 `secret.` 开头时命中；复数 `secrets` 与 `.secrets` 不命中，因此代码继续读取并拼入外部模型 context。
- **预期行为**: 明显的密钥目录必须在读取文件前被拒绝或列为 excluded。
- **实际行为**: 敏感文件内容可能被发送给外部 Provider。
- **直接证据**: `SENSITIVE_SEGMENTS` 只有 `"secret"`，匹配表达式为 `part === segment || part.startsWith(segment + ".")`；现有测试只覆盖 `.env.production`。
- **影响**: 外部数据泄露。
- **建议改法和验证点**: 将规则改为明确的敏感 basename/prefix 集合，覆盖 `secret`、`secrets`、`.secret`、`.secrets`、credential(s)、私钥后缀，并增加在 `includeUntracked` 下确认敏感文件从未进入 `read()` 的测试。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 高

### CR-02-未修复-中-归一化接受非法 severity 与负数行号
- **入口/函数**: `normalizeProviderResult()`
- **文件(行号)**: `skills/model-review-skill/scripts/lib/normalize.mjs:18-31`
- **输入场景**: Provider 返回 `severity: "urgent"` 或 `line: -1`。
- **实际分支**: severity 只检查非空字符串；line 只检查整数，非法值仍进入公共结果 envelope。
- **预期行为**: 公共契约只允许 `critical|high|medium|low`，行号必须为正整数。
- **实际行为**: 下游 Codex 或聚合器收到 schema 不兼容结果，无法可靠排序或定位。
- **直接证据**: `buildMessages()` 声明枚举，但 `normalizeProviderResult()` 未执行同一约束。
- **影响**: 结构化输出契约静默失效。
- **建议改法和验证点**: 在 normalization owner 中验证枚举和正整数，非法响应整体失败；增加对应反例测试。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中
